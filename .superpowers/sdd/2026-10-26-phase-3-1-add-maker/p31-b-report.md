## Deviations / amendments (recorded)
1. **Controller amendment to decision 7 (CWE-338):** `genPassword` draws every index from `crypto.getRandomValues` with rejection sampling and shuffles with Fisher–Yates; `rand` stays a test-only injection. Domain test: 200 generated passwords pass the rules and differ; an injected source is deterministic. `grep Math.random` on block 06: none.
2. **Task A's contract note:** `setLogin` inserts when the maker has no row and PATCHes `username` / `email` (never `vendor_id` / `created_by` / `pw_mode` on an edit — `pw_mode` is written on the insert only); the mock refuses an upsert (`on_conflict` / `Prefer: resolution=`), a PATCH of `vendor_id` / `created_by` / a server column (42501), an insert without `email` (23502); both RPCs raise P0002 without a login row (the adapter maps it to «اعمل اسم مستخدم الأول»); 22023 past 128 characters (the adapter refuses locally with «الباسورد أطول من 128 حرف» before the RPC).
3. `missing(id)` counts «الحساب البنكي» only when the caller can see bank rows (`canBank()`): without the key every maker's bank is `null` on the client and the line would wrongly say «ناقص» to ops. The admin / accounts see the full line.
4. `missing` may also name `rate` (a refused first rate) — Review Focus 4 names the rate; decision 10's list did not. `create()` also returns `reasons` (`{ step: reason }`) so the note can say why (e.g. the duplicate username).
5. The reason of a 23505 on `vendor_logins` is `duplicate_username` (not `duplicate`, which block 28 already maps to the rate message); the message is the plan's «اسم المستخدم ده مستخدم قبل كده». No change to the page's `ib:vendors` listener was needed.
6. Honesty rule: the link-mode note reads «هيوصله لينك يعمل منه الباسورد بنفسه لما بوابة المبتكر تشتغل — دلوقتي اختيارك بيتسجل بس ومفيش إيميل بيتبعت …» (the prototype's «هيوصله إيميل … صالح 48 ساعة» would have claimed a send); the note after adding with a link says «هيوصله لينك التفعيل لما بوابة المبتكر تشتغل»; with a temporary password «الباسورد المؤقت جاهز تبعته له»; the drawer's password line says «لينك التفعيل — بيتبعت مع البوابة». The e2e asserts no «اتبعت».
7. «اعمل باسورد مؤقت جديد» shows only for a maker who already has a login row: the RPC needs the row and `setLogin`'s insert is write-through (no promise), so a maker without a row gets username + e-mail first, the password in a second save.
8. Re-enabling a disabled account sets `invited` (the client may set invited / disabled only — decision 3); `active` stays the portal's.
9. The revealed password is forgotten when the drawer closes and when a new temporary password is set (found by the e2e: the stale value was still shown after a new one was set).
10. `VST` (block 28's import / export status labels) gained `leave` — part of «leave everywhere».
11. `.vs-leave` CSS tone added (the prototype's `<style>` has no `vs-leave` rule); gold like `.tg-gold`.
12. **Review A's note:** `vendor_logins.created_by` is the member's display name (`(actor && actor.name) || null`, like `vendor_rates.set_by` / `vendor_bank.updated_by`), not the auth user id — the adapter's two inserts, the mock's row and seed, the adapter tests and both specs follow it (commit after `a874aab`).
13. The success note of a write is consumed by the next page render (existing design); the drawer's two-step flow (e-mail, then a new password) keeps it visible; a single save of both shows it only until the e-mail write's reload — cosmetic, not changed.
