## Under-specified points and the choice made

1. **The transfer fixture is opt-in** (`installSupabaseMock(page, { transfer: true })`), not in the default seed: a default transfer would change Antikiano's shares and the delete test in `vendors.spec.mjs` (far beyond «the brand line or the auto brand»). The brands spec covers both the transfer made through the UI and the seeded one (the load-time attribution).
2. **The brand shape carries three keys beyond decision 3's list**: `owner` (the maker today), `lastSince` (the latest history row — the date a transfer may not go before, shown in the popup's help) and `back` (where «رجوع لصاحبه» sends it). `temp` is a boolean (`returnOn` carries the date).
3. **`vendor.brand` on an edit** logs `update: <name> (<fields>)` — the plan's `update: <fields>` with the brand's name in front, so a maker with several brands can read his log.
4. **The buttons follow the server's policy**: `canBrands()` = admin or `vendors.edit = F` (decision 5 says `canEdit()`, which admits `vendors.edit = P`; the brief wants ops to see no buttons and to be refused before any request — `vendors_followup` with `F` does see them). `setBrandRate` / the rate column follow `canRate()`.
5. **The activity sentences live in the adapter's `toEvent`** (with every other `vendor.*` verb) and block 28 shows `e.text` unchanged — decision 5 (e) is met through the same path the existing events use.
6. **`effectiveRate` mirrors `rateAt`** (the earliest row until one has started), so a brand whose only rate row is future-dated shows that rate, like a maker's. The server's `brand_owner_at` has the same «else the first row» rule for owners.
7. **A brand without an owner row** (an owner insert refused after the brand's) belongs to its origin locally (and shows in his drawer so a later row can be written); `addBrand` names the refused step in `missing` (`owner` / `rate`) and the page shows a warning, like `create()`.
8. **The local refusal messages thrown by the store are block 06's** (with the last transfer's date in them); the server's 22023 maps to `MESSAGES.brand_since_before` / `brand_same_vendor` (without the date). `returnBrand` refuses with `brand_with_origin`; `brand_return_before` covers the server's 23514 on `return_on` (the popup refuses it first).
9. **The list's search** is a union in block 28 (`vfilter`) rather than an edit of `VD.filterVendors` (decision 6 names five functions only); the phone and the other filters stay the domain's.
10. **`brandsEver`** considers a maker's rows that had started (a future-dated row does not make him a past holder); `until` = the row after his last one.
11. **`data()`** gains `brands` (the shapes) next to `vendors` / `ratesVisible`.
12. **`brands` / `brand_owners` are read with `pages()`** like `vendors` (56 today, no cap); `brand_rates` as one query like `vendor_rates`.
13. **The e2e spec drives a `DateField` like a user** (fill + Tab): a dispatched `change` leaves the input's dirty flag set, so the redraw that removes it fires a second native `change` and nests `setBody` (a `replaceChildren` error). Modals are closed with «إلغاء»: Escape reaches the drawer's handler too (pre-existing behaviour, not changed).
14. **The drawer opens on the last tab used** (`vtab` is module state, pre-existing): the spec reselects «معلومات المورد» after opening a drawer by hash.
