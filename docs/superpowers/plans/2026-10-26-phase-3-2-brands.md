## القرارات المكتوبة (وسببها وتكلفة الغلط)
1. **المفهوم في قاعدة البيانات:** البراند = الاسم اللي بيتباع بيه = في الغالب متجر Dokan. **كل صف `vendors` بياخد براند تلقائي باسمه** (زي البروتوتايب): لو الصف متجر (`woo_vendor_id` مش null) البراند بيتربط بالمتجر (`store_vendor_id = id`) وأوردرات المتجر بتتحسب لصاحب البراند يومها؛ لو مبتكر يدوي، براند من غير متجر (مش بيجيله أوردرات لحد ما ينقل له براند متجر). صاحب البراند الافتراضي = المبتكر نفسه. المبتكر اللي بنحاسبه = صاحب البراند في تاريخ الأوردر. سبب: Dokan قراءة بس، والفرعي شايل متجره، فالنقل بيتسجل عندنا بس. تكلفة الغلط: نقل غلط بيتصلح بنقل تاني من نفس التاريخ (التاريخ المتكرر مرفوض — بنعمل نقل بتاريخ بعده).
2. **الجداول (`0013_brands.sql`)** — re-runnable، grants بقايمة أعمدة، `revoke truncate, references, trigger`، تعليقات إنجليزي:
   - `brands`: `id uuid pk default gen_random_uuid()`، `name text not null` (1–80؛ **فريد على `lower(btrim(name))`** بين البراندات)، `code text not null check (code ~ '^[A-Z0-9]{1,3}$')`، `aliases text[] not null default '{}'`، `store_vendor_id uuid null unique references vendors(id) on delete cascade` (المتجر اللي أوردراته بتتباع بالبراند ده — **السيرفر بس** بيحطه)، `origin_vendor_id uuid not null references vendors(id) on delete cascade` (المبتكر اللي اتعمل له البراند)، `created_by text`، `created_at`، `updated_at`.
   - `brand_owners` (تاريخ الملكية): `id bigserial pk`، `brand_id uuid not null references brands(id) on delete cascade`، `vendor_id uuid not null references vendors(id)` (**من غير cascade**: مبتكر عليه براندات غيره مايتمسحش — 23503 → رسالة «عليه براندات»)، `since date not null`، `return_on date null check (return_on is null or return_on > since)`، `reason text` (≤ 200)، `set_by text`، `created_at`؛ `unique (brand_id, since)`. **الصفوف بتتضاف بس** (مافيش update/delete للأعضاء): النقل والرجوع صفوف جديدة. الصاحب في تاريخ D = آخر صف `since <= D`، ولو مفيش → أول صف.
   - `brand_rates` (النسبة الخاصة بتاريخ): `id bigserial`، `brand_id … on delete cascade`، `rate numeric(5,2) null check (rate is null or rate between 0 and 65)` (null = «من غير نسبة خاصة» من التاريخ ده)، `since date not null`، `set_by text`، `created_at`؛ `unique (brand_id, since)`؛ إضافة بس. RLS زي `vendor_rates`: `select`/`insert` بـ `sensitive.commission = F`.
   - RLS `brands`/`brand_owners`: `select` بـ `vendors.view <> 'N'`؛ `insert`/`update` بـ `is_admin() or vendors.edit = 'F'` (`using` التعديل = `vendors.view` نمط 0011/0012 عشان 42501 مش 0 صفوف)؛ مافيش `delete` للأعضاء (الـ cascade بس).
   - المنح: `brands` — `select` كل الأعمدة، `insert (name, code, aliases, origin_vendor_id, created_by)`، `update (name, code, aliases)`؛ `brand_owners` — `select` الكل، `insert (brand_id, vendor_id, since, return_on, reason, set_by)`؛ `brand_rates` — `select` الكل، `insert (brand_id, rate, since, set_by)`؛ `service_role` كل حاجة.
   - الحرّاس (على `anon`/`authenticated` بس، رسائل إنجليزي واضحة): `brands_guard` (before update): غير `name/code/aliases` → 42501، و`updated_at := now()`. `brand_owners_guard` (before insert): `since` أقدم من آخر `since` للبراند → 22023 `since before the last transfer`؛ `vendor_id` = الصاحب الحالي → 22023 `same vendor`.
   - **التريجر `vendors_brand_after_insert`** (after insert on `vendors`، دالة `security definer` مملوكة لـ `postgres` بـ `set search_path = public`): لو مفيش براند بنفس الاسم (lower/btrim) يضيف `brands` (name = الاسم، code من أول حرف لاتيني كبير وإلا `X`، aliases = أسماء المبتكر البديلة، `store_vendor_id` = id لو `woo_vendor_id` مش null، origin = id، `created_by = 'system'`) + صف `brand_owners` (since = `coalesce(joined_at, current_date)`). بيشتغل مع إدراج المزامنة (`service_role`) ومع الـ popup (`authenticated`) من غير تغيير في الدوال ولا في الـ adapter. لو الاسم مأخوذ: مافيش براند تلقائي (الفريق يضيفه باليد).
   - **إعادة التعبئة** في نفس الملف: نفس المنطق لكل صف `vendors` من غير براند (re-runnable بـ `not exists`). الحي: 56 صف → 56 براند + 56 صف ملكية.
   - دالتين SQL `stable` (`security invoker`، `grant execute` لـ `authenticated`/`service_role`): `brand_owner_at(p_brand uuid, p_date date) returns uuid` و`store_owner_at(p_store uuid, p_date date) returns uuid` (صاحب براند المتجر يومها، وإلا المتجر نفسه لو مفيش براند). للتقارير الجاية؛ الواجهة بتحسب محليًا.
3. **الـ adapter `IBVendors`:** مع التحميل: `brands` و`brand_owners` بقايمة أعمدة، و`brand_rates` لو `canRate()` (مرفوض/فاضي → مافيش نسب خاصة معروفة). شكل المبتكر بيكسب `brands` (اللي عنده دلوقتي: `{ id, name, code, aliases, since, returnOn, temp, rate, store, origin }`) و`brandsEver` (اللي كان عنده ومش عنده: `{ …, until, now: اسم الصاحب الحالي }`). دوال: `addBrand(vendorId, { name, code, aliases, rate, since }, actor)` (غير متزامن: إدراج البراند → صف ملكية → صف نسبة لو فيه نسبة وcanRate)، `updateBrand(id, { name, code, aliases }, actor)` (PATCH الأعمدة المتغيرة)، `setBrandRate(id, rate|null, since, actor)` (إدراج)، `transferBrand(id, toVendorId, { since, returnOn, reason }, actor)` (إدراج صف ملكية؛ محليًا: `since ≥` آخر since، `toVendorId ≠` الصاحب الحالي، `returnOn > since`)، `returnBrand(id, { since }, actor)` (لـ `temp.back` وإلا `origin`؛ مرفوض لو هو أصلًا عنده)، `ownerAt(brandId, date)`، `storeOwnerAt(storeVendorId, date)` (المتجر نفسه لو مفيش براند)، `rateFor(storeVendorId, date)` (النسبة الخاصة السارية وإلا نسبة الصاحب يومها عبر `rateAt`)، `brandByName(name)` (الاسم أو الأسماء البديلة، منسّق)، `namesOf(vendorId)` (اسمه + بدائله + أسماء برانداته الحالية والسابقة — للبحث). أحداث العميل: `vendor.brand` (`add: <name>` / `update: <fields>`)، `vendor.brand.rate` (`<name>: <rate|—> من <since>`)، `vendor.brand.transfer` — **صفين**: على المبتكر الناقل وعلى المستلم (`new_value` = «<name> → <to> من <since>[ لحد <returnOn>]»)، `vendor.brand.return` كذلك. مافيش باسورد ولا أرقام حساسة في أي `new_value`.
