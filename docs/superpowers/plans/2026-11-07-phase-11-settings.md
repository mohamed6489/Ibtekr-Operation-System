# المرحلة 11 — صفحة الإعدادات على بيانات حقيقية

الدفتر: `.superpowers/sdd/2026-11-07-phase-11-settings/progress.md`. الأساس: نسخة الـ prototype v6 (`Prototype file/نظام إبتكر v6 (7 نوفمبر).html`،
الكتلة 20 هناك = صفحة الإعدادات، 14 قسم + hub كروت؛ والكتلة 14 هناك فيها `IBQuick` «الإجراءات السريعة»). الصفحة لسه عليها soon
(`SOON = ['settings']` في الكتلة 28) فالـ prototype هو الأساس: كتلتنا `17-page-settings.js` (النسخة القديمة من نفس الصفحة) بتتبدل بالكتلة 20 بتاعة
الـ v6 وبعدها بتتعدّل على `IBSettings` — تعديل ومسح عادي، وبتتضاف لـ `EDITED` + `npm run lock`.

## اللي فهمته من الـ prototype (v6)

- **الـ hub:** 4 مجموعات كروت (الشركة والفريق: عام · الفريق والصلاحيات · الأوراق الرسمية · الهوية البصرية / الربط والأدوات: الربط بالمنصات ·
  تعليمات الذكاء الاصطناعي · الإجراءات السريعة / التشغيل: المبتكرين · التنبيهات · القوائم والحالات · الحسابات والدفع / الأمان والبيانات: الأمان ·
  سجل النشاط · البيانات)، كل كارت بحالة مختصرة و«تفاصيل» بيفتح صفحة القسم (`#settings-<قسم>`)؛ في كل صفحة زرار «حفظ» وعلامة «تغييرات مش
  محفوظة» وشريط حفظ/تجاهل تحت، والخروج من القسم بتغييرات = بوب أب «لازم تحفظ الأول».
- **عام:** بيانات الشركة (اللوجو → الهوية، الاسم، القانوني، الإيميل، الموقع، العنوان، الهاتف)، اللغة والمنطقة، تفضيلات العرض (4 مفاتيح).
- **الفريق والصلاحيات:** الأعضاء (بحث، تحديد جماعي: تغيير الدور / إيقاف / تفعيل / إعادة إرسال، الدور من select، قنوات خدمة العملاء، صلاحيات
  مخصصة، تنبيهات مخصصة، فتح الملف، إيقاف بسبب) · الأدوار والصلاحيات (شيبس الأدوار + «دور مخصص»، مصفوفة ✓/▣/☐ بمجموعات قابلة للطي، الصفوف
  الحساسة بتأكيد، بوب أب الدور: البيانات/الصلاحيات/التنبيهات/الملخص اليومي/حذف الدور بنقل أعضائه) · الدعوات المعلّقة.
- **الربط بالمنصات:** 4 كروت أرقام (متصلة · فيها خطأ · أحداث اليوم · أخطاء 24 ساعة) + 4 تابات (الموقع والبيانات · وسائل التواصل والرسايل ·
  الإعلانات · الذكاء الاصطناعي و API) بـ 16 كارت منصة (ربط / الإعدادات / فصل / ربط تاني) + «ربط أداة جديدة» (API Key / MCP / OAuth) + سجل
  المزامنة + صفحة WooCommerce لوحدها (الرابط، Consumer key/secret، اختبار الاتصال، اتجاه المزامنة، التعارض، الكيانات، خريطة الحالات والحقول،
  فصل) + صفحة واتساب (الأرقام).
- **تعليمات الذكاء الاصطناعي:** 3 تابات (الصور: قواعد الخانات الأربعة + الستايل + الباترن + الممنوع + مرجعيات / الفيديو: الافتراضيات / المحتوى:
  أسلوب الكتابة) وأقسام فرعية («المنتجات» + «البوست» + أقسام يضيفها الأدمن) و«رجّع للافتراضي» / «احفظ».
- **إعدادات المبتكرين:** قواعد التأخير الافتراضية + قواعد خاصة لكل مبتكر + التنشيط وإيقاف التنشيط (اقتراحات تلقائية بموافقة) + الافتراضيات عند
  الإضافة + بيانات الدخول والحساب البنكي (التغطية).
- **التنبيهات:** 7 تابات: أنواع التنبيهات (8 أقسام × صفوف: مفعّل، مدة الظهور، التكرار، القنوات، المستلم، قالب) · حسب الدور (مصفوفة يستلم/يشوف
  بس/لا بحارس الصلاحيات) · التصعيد (بعد مدة → دور/شخص على قناة) · الحسابات والاشتراكات (يوم المرتبات، دورة كشوف المبتكرين، تنبيه الاشتراكات) ·
  التوصيل (المسؤول وبيانات المخزن) · تقارير المهام (تجميع تنبيهات في تقرير بميعاد + ملخص يومي تلقائي لكل دور) · ساعات الهدوء.
- **القوائم والحالات:** حالات الأوردر (مقابل WooCommerce، الترتيب)، التأكيد، الفرعي، أسباب الإلغاء والمسح، المرتجع، المصروفات، فئات المبتكرين،
  أسباب الإيقاف.
- **الحسابات والدفع:** حسابات الشركة (الحساب الفعلي)، تحويل مستحقات المبتكرين، الفاتورة وكشف الحساب.
- **سجل النشاط:** الجدول بفلاتر (العضو، الصفحة، النوع، الفترة) + CSV + إعدادات السجل (تسجيل العرض الحساس، تنبيه تغيير الصلاحيات، نسخة يومية).
- **الأمان:** حسابي (كلمة السر، 2FA)، الجلسات النشطة (خروج من جهاز / من الكل)، سياسات الشركة (إلزام 2FA، القفل بعد 5 محاولات، انتهاء الجلسة،
  إخفاء الحساس، منع التصدير، IP، الحد الأدنى لكلمة السر، مدد الجلسة).
- **الأوراق الرسمية:** رفع ورقة (PDF/صورة، النوع، الرقم، الإصدار، الانتهاء، ملاحظات) + بحث + تنبيه قبل الانتهاء بـ 30 يوم.
- **الهوية البصرية:** المعاينة + فحص التباين، 3 لوجوهات (فاتح / على الأخضر / الأيقونة)، كل ألوان السيستم (أساسية، خلفيات، نصوص، حدود، حالات،
  رسوم) بالتابع والأصلي، الخطوط — وبيتطبق على السيستم كله فورًا.
- **البيانات:** تصدير المجموعات (بالأعمدة والفترة والصيغة)، الاستيراد بمعالج (الملف → ربط الأعمدة → المراجعة → النتيجة → تراجع)، قوالب الشيتات،
  النسخ الاحتياطي والاحتفاظ، منطقة الخطر.
- **الإجراءات السريعة:** إدارة روابط بفلاترها في القايمة اللي فوق (`IBQuick`).

## قرارات صاحب المشروع (7 نوفمبر)

1. **الصفحة كلها مرة واحدة** — الـ 14 قسم على بيانات حقيقية في مرحلة واحدة (مش على أجزاء).
2. **مفاتيح الويب سايت من الصفحة بتست + تأكيد:** الأدمن يكتب رابط المتجر + Consumer key/secret + مستخدم وباسورد تطبيق WordPress → «اختبار
   الاتصال» (GET من السيرفر) → تأكيد → تتحفظ في Vault، وكل الدوال تقرا Vault الأول وبعده أسرار Supabase الحالية (احتياطي). ده نفسه طريق
   التحويل من الـ staging للحي.
3. **تبديل مزوّد الـ AI = افتراضي لكل قسم + تبديل لكل أداة:** مزوّد افتراضي للنصوص وواحد للصور (وواحد للصوت وواحد للفيديو)، قايمة موديلات
   ثابتة لكل مزوّد، وأي أداة (أوصاف المنتجات، كتابة التسويق، الميديا باير، صور الاستوديو، صور الكامبين، الفويس، الفيديو) تقدر تاخد مزوّد مختلف.
   الاستوديو بالـ Space (فلو Magnific) يفضل Magnific.
4. **قسم MCP = السيستم عميل MCP:** عرض وإدارة سيرفرات MCP اللي السيستم بيتصل بيها (Magnific متربط دلوقتي؛ Higgsfield؛ وأي سيرفر MCP عام
   بالرابط + OAuth أو مفتاح) بحالة كل ربط وأدواته. السيستم كسيرفر MCP مرحلة لوحدها بقرار مكتوب.
5. **كل كروت الـ v6 الـ 16:** اللي مالوش تنفيذ عندنا (Airtable · Google Sheets · Paymob · بوسطة · n8n · GitHub · Figma) يبان «غير متصل»، ومفتاحه
   يتحفظ في Vault من غير ما حد يستخدمه لسه (التنفيذ لما يبقى له مرحلة).
6. **مزوّدين بيتنفّذوا فعلًا:** Gemini (نصوص + صور Nano Banana بمفتاح Google AI Studio واحد)، OpenAI gpt-image للصور (نفس مفتاح النصوص)،
   ElevenLabs مباشر للصوت، Higgsfield للفيديو — و«شوف إيه تاني ممكن يتضاف نضيفه» (قرار التنفيذ 15).
7. **التنبيهات = منطق الـ prototype بالظبط** («فهمني المطلوب في البروتوتايب نعمله ولا هنزود ولا هنقص بس يبقى logic»): كل تابات القسم
   السبعة بتشتغل فعلًا — مش عرض (التفاصيل في قرار التنفيذ 16، والقنوات الخارجية في الأسئلة المفتوحة).
8. **القوائم والحالات عرض بس** — من الداتابيز والكود، من غير تعديل في المرحلة دي.
