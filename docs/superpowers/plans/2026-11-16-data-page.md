قوالب و هكذا» (البيانات) · «الاستيراد مش شغال … هستخدمه ف تحديث بيانات السيستم عن طريق اني اعمل تصدير للقالب املي فيه الداتا ثم استيراد · اظبط شكل

**إجاباته (الأسئلة في الشات):** الصف الموجود = «الخانات المكتوبة بس بتتعدّل» (الفاضية بتفضل زي ما هي) · التعرّف على السجل = «عمود ID من السيستم»
· اللي ليه نسخة على الموقع = «السيستم + الموقع مع بعض» (نفس طريق التعديل باليد) · المسح = «يختار بالقسم».

## القرارات
1. **«القوائم والحالات»:** قايمة جانبية بالقوائم في مجموعات (الحالات · الأسباب · قوائم تانية) وعدد كل قايمة، والقايمة المختارة في كارتها جنبها؛ على
   الموبايل صف تابات بيتسحب. العناصر `role=tab` (الكيبورد والاختبارات زي ما هي). الكتلة 17 + `settings.css`.
2. **«البيانات» بتابات:** تصدير · استيراد · القوالب · النسخة الكاملة · منطقة الخطر (`st.dtab`). قسم «النسخ الاحتياطي والاحتفاظ» القديم كان مفاتيح
   شكلية مابتعملش حاجة («إنشاء نسخة الآن» = رسالة بس) — اتشال، ومكانه «النسخة الكاملة» (ملف Excel حقيقي بكل المجموعات) وملحوظة إن نسخ قاعدة
   البيانات من Supabase نفسه.
3. **الاستيراد بالـ ID (`01-dataio.js` وضع `mixed`):** كل شيت بيتعدّل فيه أول عمود «ID» (التصدير والقالب بيطلّعوه). صف فيه ID = تعديل للسجل ده بالخانات
   المكتوبة بس (الفاضية بتفضل)، ID مش موجود = خطأ؛ صف من غير ID = جديد (بالخانات المطلوبة) لو الشيت بيقبل إضافة، وإلا خطأ «لازم ID»؛ جديد اسمه
   موجود بالفعل = «موجود — حط الـ ID بتاعه عشان تعدّله» ويتخطّى. مافيش اختيار «إضافة / تعديل» تاني. الحروف العربي بتتطابق من غير الهمزات والتاء
   المربوطة والياء، و«الفئة» للمبتكر أكتر من واحدة بـ «،».
4. **الكتابة من غير اختصارات:** كل شيت بيكتب عبر نفس الـ adapter اللي الصفحة بتكتب بيه، فاللي ليه نسخة على الموقع بيتبعت زي التعديل باليد
   (`IBVendors.store.update` ← `push_vendor`، البنك ← `setBank`، النسبة ← `setRate`، الأوردر ← `OrdersApp.patch`، المنتج ← `OrdersApp.patchLine` بـ ID
   السطر — **الكتلة 29 بقرار ده**). النتيجة بتتعد صف صف (اتعمل / اترفض بسببه). الشيتات اللي كانت بتكتب في داتا الـ prototype القديمة (الفريق الأولاني،
   الحضور، الإجازات، تقييمات KPI، المخزن، المشاوير، قواعد التأخير) بقت **تصدير بس من البيانات الحقيقية** أو اتشالت — الفريق بيتعدّل بالـ ID (الاسم
   والموبايل والمسمى — `IBHR.memberInfoSet`) والعطلات بتتضاف (`IBHR.holidayAdd`).
5. **القالب:** بوب أب منظم — الشيت، والقالب «بالبيانات الحالية» (للتعديل — فيه الـ ID) أو «فاضي» (للإضافة)، وجدول الأعمدة (مطلوب للجديد / اختياري /
   ثابت) بالقيم المسموحة، و«نزّل Excel» (ملف حقيقي) و«نسخ للصق في Google Sheets».
6. **منطقة الخطر (`0117`):** RPC `data_wipe(p_sections text[], p_confirm text, p_dry boolean)` — الأدمن بس بجلسة aal2 لو عنده 2FA؛ الأقسام بقايمة ثابتة
   على السيرفر (الأوردرات · المبتكرين · المنتجات · الحسابات · المخزن · خدمة العملاء · طلبات الفريق · التسويق · سجلات الموارد البشرية · السجلات)،
   `p_dry` بيرجّع عدد الصفوف لكل جدول وأي جداول تانية بتشاور عليهم (FK): بتتفك (set null) أو بتتمسح معاهم (cascade) أو بتوقف المسح (restrict /
   جدول مالوش قسم)؛ التنفيذ `DELETE` (مش `truncate … cascade` — كانت هتفضّي جداول برّه الاختيار كلها) لجداول القسم الموجودة بس وبعد ما الأدمن يكتب
   «امسح البيانات»؛ الفريق والأدوار والإعدادات والقوائم والبراند بيفضلوا دايمًا. صف في `activity_log` `settings.data.wipe` بأسماء
   الأقسام والأعداد. الملفات المرفوعة (Storage) مابتتمسحش. الربط بالموقع بيفضل زي ما هو — الواجهة بتقول «غيّر الربط الأول وإلا المزامنة هترجّع
   البيانات».
